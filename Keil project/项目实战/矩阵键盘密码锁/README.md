# 矩阵键盘密码锁

> 4×4 矩阵键盘输入 4 位密码，LCD1602 显示输入状态与开锁结果

## 功能

- 上电显示 `PASSWORD LOCK`，第 2 行是 `Code: _ _ _ _`；
- `S1 ~ S9` 输入 1~9，`S10` 输入 0，每输入一位显示一个 `*`；
- `S11` 删除一位（退格），`S12` 确认；
- 4 位密码正确 → 显示 `OPEN`；错误 → `ERROR`；不足 4 位 → 提示 `4 DIGITS`；
- 结果停留 2 秒后自动清空，回到输入界面；
- 默认密码 **1234**，改 `PASSWORD` 数组即可。

## 按键映射

| 按键 | 功能 |
|:---|:---|
| S1 ~ S9 | 数字 1 ~ 9 |
| S10 | 数字 0 |
| S11 | 删除最后一位 |
| S12 | 确认 / 开锁 |
| S13 ~ S16 | 保留（可扩展“改密码”“上锁”） |

## 硬件接线

| 模块 | 引脚 | 说明 |
|:---|:---|:---|
| 矩阵键盘 | `P1.7~P1.4` 行、`P1.3~P1.0` 列 | 与键盘实验相同 |
| LCD1602 | `P0.0~P0.7` 数据，`RS=P2.6`、`RW=P2.5`、`E=P2.7` | 与 LCD 实验相同 |

> ⚠️ 普中 A2 上 **P2.5 ~ P2.7 与 LED、蜂鸣器共用**：接了 LCD 就不要同时用 LED/蜂鸣器，
> 否则 LCD 控制线会把 LED 点亮/闪烁，蜂鸣器也可能误响。本项目只做“键盘 + LCD”。

## 软件结构

```
项目实战/矩阵键盘密码锁/
├── User/main.c                 ← 应用层：按键 → 密码状态机 → 显示
├── Driver/
│   ├── MatrixKey_Scan.c/.h     ← 矩阵键盘驱动（逐列扫描，可换线翻转版）
│   └── LCD1602.c/.h            ← LCD1602 驱动（初始化、定位、显示字符串）
├── System/Delay.c/.h           ← 毫秒延时
├── Startup/STARTUP.A51
└── Project.uvproj
```

`main.c` 里不出现任何 `P1`、`P2`；它只调用“扫描键盘”“显示字符串”“延时”三个模块。

## 运行流程

```
上电
 ├─ LCD 初始化，显示 PASSWORD LOCK / Code: _ _ _ _
 └─ 主循环：读键 → 边沿判断 → 分发
        │
        ├─ 数字键：位数 < 4 ? 追加并刷新 : 忽略
        ├─ S11   ：位数 > 0 ? 回退并刷新 : 忽略
        └─ S12   ：
              ├─ 位数 != 4 → 显示 "4 DIGITS"（0.8s）→ 回输入
              └─ 位数 == 4 → 逐位比对
                    ├─ 正确 → "OPEN"  （2s）→ 清空 → 回输入
                    └─ 错误 → "ERROR" （2s）→ 清空 → 回输入
```

## 关键设计，为什么这样写

### 1. “按一次只算一次”：`LastKey` 边沿检测

矩阵键盘驱动是**按住期间持续返回同一个键号**（这是为了“按住点亮”那个实验设计的）。
如果密码锁直接拿返回值当动作，按住 S1 不放，主循环会一轮接一轮地追加 1，瞬间填满 4 位。

所以 `main` 里保存上一轮的键号：

```c
if (Key == LastKey) continue;   /* 同一个键还按着：不重复处理 */
LastKey = Key;                  /* 记住这个键 */
if (Key == 0) continue;         /* 松手：也不处理 */
```

效果：

- 按住 S1：第一轮处理一次，后面 `Key == LastKey` 全部跳过；
- 松手：`Key = 0`，`LastKey` 变成 0；
- 再按 S1：`0 != 1`，又算一次。

这叫**边沿检测**（只认“从无到有”的那一刻）。做按键菜单、计算器、密码锁都离不开它。

### 2. 密码为什么放在 `code` 数组里

```c
unsigned char code PASSWORD[4] = {1, 2, 3, 4};
```

`code` 让数组落在 **Flash（ROM）**，不占宝贵的 128 字节 RAM。
密码是常量，运行时不会改，放 Flash 正合适。

> 以后要做“改密码”，就得把密码搬到 `EEPROM`（AT24C02）或 RAM + 掉电保存，
> 那是 I2C 章节的内容。

### 3. 为什么显示 `*` 而不是数字

```c
Line[6 + i * 2] = (i < InputCnt) ? '*' : '_';
```

密码锁旁边可能站着别人，直接显示数字等于把密码念出来。
`*` 表示“这一位已经有内容”，`_` 表示空位，用户能看出还差几位，却看不到具体数字。

### 4. 为什么位数不足不直接判错

输入 4 位之前按 S12，只提示 `4 DIGITS`，**不清空已有输入**。
这样用户输错一位时，可以先按 S11 退格再改，而不是从头再来。
真正的“错误”只留给“位数够但内容不对”。

### 5. 为什么结果用 `Delay_ms(2000)` 停 2 秒

第一版图简单：显示结果 → 等 2 秒 → 清空。
代价是这 2 秒里键盘完全不响应（阻塞）。对密码锁来说可以接受，因为结果展示期间
本来也不该继续输入。

以后学了定时器，可以改成“非阻塞提示”：用定时器计数 2 秒，主循环继续扫描，
甚至能做到“按住 S12 不放自动重试”。

### 6. 逐位比对，不拼成一个整数

```c
for (i = 0; i < 4; i++)
    if (InputBuf[i] != PASSWORD[i]) return 0;
```

比 `InputBuf[0]*1000 + ... == 1234` 好：

- 支持前导 0（密码可以是 0123）；
- 位数改了只改 `PASSWORD_LENGTH`，公式不用重写；
- 一眼能看出“逐位比较”。

## 上板测试步骤

1. Keil 打开 `Project.uvproj`，Build，用 STC-ISP 下载 `Objects/project.hex`；
2. 上电应看到 `PASSWORD LOCK` / `Code: _ _ _ _`；
3. 按 `1 2 3 4`，第 2 行应依次变成 `* _ _ _` → `* * _ _` → `* * * _` → `* * * *`；
4. 按 `S12` → 显示 `OPEN`，2 秒后回到输入；
5. 按 `1 2 3 5` + `S12` → 显示 `ERROR`；
6. 按 `1 2 3` + `S12` → 显示 `4 DIGITS`，同时已输入的 3 位保留；
7. 按 `1 2` + `S11` → 变回 `* _ _ _`。

## 常见问题

| 现象 | 排查 |
|:---|:---|
| LCD 全黑/全亮 | 对比度电位器没调；或 P0 排线接反 |
| 屏幕有字但乱码 | 初始化延时不够、接线松动、或 P0 与数码管模块冲突（都接在 P0，不能同时插） |
| 按键没反应 | 矩阵键盘插 P1；P1 是否被 NRF/步进电机占用 |
| 按一下出现好几位 | `LastKey` 边沿检测没写对，或把 `Key == LastKey` 判断成了 `=` |
| 显示 `ERROR` 但密码对 | 键号映射反了（S1 是不是 1）；或 `PASSWORD` 数组与预期不一致 |

## 可以继续做

1. **错误次数限制**：连续错 3 次锁定 30 秒（计数 + 定时）；
2. **改密码**：S13 进入改密模式，新密码存 AT24C02（I2C 章节）；
3. **真开锁**：用 P3 的空闲脚驱动继电器/舵机（注意别占用 P3.0/P3.1 串口）；
4. **声音提示**：蜂鸣器与 LCD 的 RW 共用 P2.5，需分时复用或改线；
5. **非阻塞提示**：用定时器中断计时，替代 `Delay_ms(2000)`。
