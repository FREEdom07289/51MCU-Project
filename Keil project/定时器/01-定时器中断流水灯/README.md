# 01-定时器中断流水灯

> 用定时器 1ms 中断做节拍，每 500ms 移一位流水，主循环里**不用 Delay**

## 现象

上电后 D1 → D8 依次点亮，每 500ms 移动一位，循环往复。
和之前"`Delay_ms(500)` + 移位"的流水灯看着一样，但**计时方式完全不同**：
这次 CPU 不再空转等待，时间由硬件定时器在后台数。

## 为什么值得单独做一个实验

| | `Delay_ms()` 版本 | 定时器中断版本 |
|:---|:---|:---|
| 计时原理 | CPU 空循环数数 | 硬件计数器溢出，自动进中断 |
| 精度 | 受编译优化、中断影响，误差大 | 由晶振决定，稳定 |
| CPU 占用 | 延时期间 100% 空转 | 中断只占几微秒，其余时间空闲 |
| 扩展性 | 一个延时只能干一件事 | 1ms 节拍可同时服务按键、数码管、PWM |

**定时器是"从会点灯到会做系统"的分水岭**：有了它，才能做"按键不卡、显示不闪、呼吸灯"。

## 51 定时器怎么数时间

定时器本质是一个**加 1 计数器**，每个机器周期加 1：

```
晶振 11.0592MHz → 12 分频 → 机器周期 12 / 11.0592MHz ≈ 1.085us
```

- T0 方式 1：16 位计数器，从初值数到 65536 溢出，置位 `TF0`；
- 溢出 → 若 `ET0=1` 且 `EA=1` → 跳转到中断号 1 的服务函数；
- 方式 1 **不会自动重装**，所以中断里必须手动写回 `TH0/TL0`。

### 1ms 初值怎么算

```
1ms 需要的计数 = 1000us / 1.085us ≈ 922
初值 = 65536 - 922 = 64614 = 0xFC66
→ TH0 = 0xFC，TL0 = 0x66
```

常用初值（@11.0592MHz）：

| 定时 | 初值 | TH0 | TL0 |
|:---:|:---:|:---:|:---:|
| 1ms | `0xFC66` | `0xFC` | `0x66` |
| 5ms | `0xF738` | `0xF7` | `0x38` |
| 10ms | `0xEE00` | `0xEE` | `0x00` |
| 50ms | `0x4C00` | `0x4C` | `0x00` |

## 工程结构

```
01-定时器中断流水灯/
├── User/main.c              ← 应用层：每 500ms 移一位
├── Driver/LED.c/.h          ← 驱动层：P2 口点灯
├── System/Timer0.c/.h       ← 系统层：1ms 节拍 + 毫秒计数
├── Startup/STARTUP.A51
└── Project.uvproj
```

`Timer0` 放在 `System/`，因为它是"单片机内置的资源"，和延时、串口同级；
`main` 只负责"到点了就移一位"，不碰 `TMOD`、`TH0` 这些寄存器。

## 代码逐段看

### 1. 初始化

```c
TMOD &= 0xF0;    /* 清掉 T0 的低 4 位，保留 T1 的设置 */
TMOD |= 0x01;    /* T0：方式 1（16 位定时） */

TH0 = 0xFC;
TL0 = 0x66;

ET0 = 1;         /* 允许 T0 中断 */
EA  = 1;         /* 打开总中断 */
TR0 = 1;         /* 启动 T0 */
```

- **为什么 `TMOD &= 0xF0` 再 `|=`**：`TMOD` 不可位寻址，不能 `TMOD |= 0x01` 就完事——
  那样会保留 T0 原来的高 2 位（GATE、C/T），万一之前是计数器模式就错了。
  先清 4 位再写，才是标准姿势。
- **为什么先装初值再 `TR0=1`**：反过来会先从一个随机值开始数，第一次溢出时间不准。
- **`ET0` 和 `EA` 都要开**：`ET0` 是"允许这个中断"，`EA` 是"允许所有中断"。

### 2. 中断服务函数

```c
void Timer0_ISR(void) interrupt 1
{
    TH0 = 0xFC;
    TL0 = 0x66;
    Timer0_Ms++;
}
```

- `interrupt 1` 是 T0 的中断号（T1=3、INT0=0、INT1=2、串口=4）；
- 方式 1 不自动重装，**忘了重装就只进一次中断**，这是最常见的坑；
- 中断里只做"重装 + 计数"。绝不能在中断里 `Delay`、刷 LCD、打印串口——
  中断要尽快返回，否则主循环和其他中断都被拖住。

### 3. 共享变量为什么加 `volatile`

```c
static volatile unsigned int Timer0_Ms = 0;
```

`Timer0_Ms` 在中断里改、在主循环里读。编译器看不到"中断随时会改它"，
可能把它缓存进寄存器，导致主循环读到的是旧值。
`volatile` 告诉编译器：**每次都去内存重新读，不要优化**。

规则：**跨中断共享的变量，必须 `volatile`**。

### 4. 读 16 位计数为什么要关中断

```c
ET0 = 0;
Value = Timer0_Ms;   /* 51 是 8 位机，读 2 字节要分两次 */
ET0 = 1;
```

如果读到低字节后正好来中断把高字节加了 1，就会读到"半新半旧"的值
（例如 0x00FF 变成 0x0100，读成 0x0100 或 0x00FF 都可能错）。
关中断只持续几条指令，代价很小，换来一次可靠的 16 位读取。

### 5. 主循环：到点才动，其余时间自由

```c
if ((unsigned int)(Timer0_GetMs() - LastMs) >= STEP_MS)
{
    LastMs += STEP_MS;
    Pattern = _crol_(Pattern, 1);
    LED_WriteAll(Pattern);
}
```

- **无阻塞**：没到 500ms 就立刻返回，主循环可以干别的（以后加按键扫描、显示刷新）；
- **`LastMs += STEP_MS` 而不是 `= now`**：固定节拍累加，避免每次判断/执行的小误差累积；
- **无符号减法**：`now - last` 在计数器回绕（约 65.5 秒）时仍然正确，
  前提是间隔远小于 32 秒。

## 上板现象

- D1 亮 500ms → D2 亮 500ms → … → D8 → 回到 D1；
- 用秒表计时，10 步约 5 秒，误差应很小；
- 想改速度只改 `STEP_MS`，不需要改定时器初值。

## 常见坑

| 现象 | 原因 |
|:---|:---|
| 只闪一下就停 | 中断里忘了重装 `TH0/TL0`（方式 1 不自动重装） |
| 完全不进中断 | `EA=0`、`ET0=0`、或忘了 `TR0=1` |
| 时间明显不对 | 初值按 12MHz 算的；普中 A2 是 11.0592MHz |
| 主循环读到旧值 | `Timer0_Ms` 没加 `volatile` |
| 偶尔读到错误时间 | 16 位变量没做原子读（没关 ET0） |
| 程序跑飞/变慢 | 在中断里做了耗时操作（延时、显示、串口打印） |
| 数码管/按键变卡 | 中断太频繁或中断里干了重活 |
