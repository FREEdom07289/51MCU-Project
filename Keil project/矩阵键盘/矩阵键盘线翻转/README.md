# 矩阵键盘线翻转（4×4）

> 同一个键盘、同一个接口，换一种扫描思路：**两次翻转**读出列号和行号

## 现象

和逐列扫描版完全一样：按住 **S1 ~ S8** 点亮 **D1 ~ D8**，松开全灭；
**S9 ~ S16** 能识别，但 `main` 暂不处理。

## 和"逐列扫描"版的区别

| | 逐列扫描（`../矩阵键盘扫描/`） | 线翻转（本目录） |
|:---|:---|:---|
| 思路 | 一次拉低一列，读行 | 先"行低读列"，再"列低读行" |
| 循环次数 | 4 列 × 每列一次检测 | 固定两次检测 |
| 消抖 | 检测到按下时做一次 | 检测到按下时做一次 |
| 对外接口 | `MatrixKey_Scan()` | `MatrixKey_Scan()`（**完全相同**） |
| `main.c` | 不变 | **一行都不用改** |

> 这正是模块化的好处：`.h` 里的函数名和返回值不变，换实现不影响调用者。

## 原理：把"输出/输入"翻过来

矩阵键盘的 8 根线，**行和列都可以当输出，也都可以当输入**（51 的准双向口）。
线翻转法就是利用这一点，分两步走：

### 第 1 步：行线输出 0，列线当输入 → 读出"哪一列"

```c
KEYPAD_PORT = 0x0F;          /* P1.7~P1.4 = 0（行输出0），P1.3~P1.0 = 1（列弱上拉） */
```

- 行线被强行拉低；
- 列线写 `1`，只是弱上拉，可以被按键拉低；
- 按下某个键，这个键把"它所在的列"和"它所在的行（低电平）"短接 → **这一列被拉低**；
- 读 `P1 & 0x0F`，哪一位是 `0`，就是第几列。

| 列线读回 | 被拉低的引脚 | 第几列 |
|:---:|:---|:---:|
| `0x07` | P1.3 | 1 |
| `0x0B` | P1.2 | 2 |
| `0x0D` | P1.1 | 3 |
| `0x0E` | P1.0 | 4 |

### 第 2 步：翻转 → 列线输出 0，行线当输入 → 读出"哪一行"

```c
KEYPAD_PORT = 0xF0;          /* P1.3~P1.0 = 0（列输出0），P1.7~P1.4 = 1（行弱上拉） */
```

同一个键，现在把"它所在的行"和"它所在的列（低电平）"短接 → **这一行被拉低**；
读 `P1 & 0xF0`：

| 行线读回 | 被拉低的引脚 | 第几行 |
|:---:|:---|:---:|
| `0x70` | P1.7 | 1 |
| `0xB0` | P1.6 | 2 |
| `0xD0` | P1.5 | 3 |
| `0xE0` | P1.4 | 4 |

两次结果组合：**键号 = 行 × 4 + 列 + 1**。

> 整个过程中，同一个键先"暴露列"、再"暴露行"——所以叫"线翻转"，
> 也有人叫"行/列反转扫描"。它不需要 4 段重复的代码，只有固定两段。

## 关键代码

```c
/* ① 行低读列 */
KEYPAD_PORT = 0x0F;
ColState = KeyPad_ReadCol();                 /* P1 & 0x0F */
if (ColState == 0x0F) { KEYPAD_PORT = 0xFF; return 0; }   /* 没有列被拉低 */

Delay_ms(10);                                /* 消抖 */
ColState = KeyPad_ReadCol();
if (ColState == 0x0F) { KEYPAD_PORT = 0xFF; return 0; }   /* 抖动 */

Col = KeyPad_ColToIndex(ColState);           /* 0x07→0，0x0B→1… */

/* ② 翻转：列低读行 */
KEYPAD_PORT = 0xF0;
RowState = KeyPad_ReadRow();                 /* P1 & 0xF0 */
KEYPAD_PORT = 0xFF;                          /* 读完立即释放端口 */

if (RowState == 0xF0) return 0;              /* 两次之间手指松开了 */
Row = KeyPad_RowToIndex(RowState);           /* 0x70→0，0xB0→1… */

return (unsigned char)(Row * 4 + Col + 1);
```

### 为什么读列时只看低 4 位、读行时只看高 4 位

- 读列阶段：高 4 位是**自己刚写的 0**（行输出），读回来恒为 0，没有信息；
- 读行阶段：低 4 位是**自己刚写的 0**（列输出），同样没有信息。
- 所以两次都要用掩码 `& 0x0F` / `& 0xF0` **只取真正作输入的那一半**。

### 为什么最后要写 0xFF

不管哪一步，端口总有一半是低电平。读完后把 8 根线全部放回高（弱上拉），
长按的时候就不会一直对地导通；下次扫描也从干净状态开始。

### 为什么"两次之间可能松手"

第 1 步确认按下后，到第 2 步只隔几条指令，但手指仍可能在这几微秒内松开。
松开后第 2 步读到的就是 `0xF0`（没有行被拉低），此时必须返回 0，
否则会把"上一次按下的列"和"没读到的行"拼成一个错误键号。

## 两种方法怎么选

| 关注点 | 逐列扫描 | 线翻转 |
|:---|:---|:---|
| 代码直观 | 一列一列看，最贴近"扫描"的表象 | 需要先理解"行/列角色互换" |
| 代码量 | 4 段结构相同，可以用 for 收敛 | 固定两段，天然更短 |
| 多键行为 | 同列多键只认上面一行 | 同列多键只认上面一行；三键 L 形可能出现鬼键 |
| 实测代码体积 | `code=226B` | `code=245B` |
| 适用 | 初学、需要逐列调试时 | 理解了原理后，写起来更快 |

> 代码体积略大不代表方法差：这里多了两个"列/行换算"函数，换来的是一眼就能
> 看懂的两段式流程。真正要抠字节时，可以直接查表或合并 switch。

## 常见坑

| 现象 | 原因 |
|:---|:---|
| 永远检测不到键 | `0x0F` / `0xF0` 写反：行低读列、列低读行，别混 |
| 读到"假列" | 读列时把高 4 位也拿来判断（那是自己输出的 0） |
| 键号错位 | 列号、行号换算时位序反了：列看 P1.3→P1.0，行看 P1.7→P1.4 |
| 偶尔返回 0 | 两次翻转之间松开手指，属于正常保护 |
| 松开后仍亮 | 忘了最后 `KEYPAD_PORT = 0xFF`，或 `main` 的 `else` 没灭灯 |
