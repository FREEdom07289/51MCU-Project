# 矩阵键盘扫描（4×4）

> 8 根 IO 线读 16 个按键：逐列拉低 + 读行线，按住 S1~S8 点亮 D1~D8

## 实验现象

- 按住 **S1 ~ S8** 中任意一个：对应的 **D1 ~ D8** 点亮；
- 松开：全部熄灭；
- **S9 ~ S16** 暂不参与控制（代码已能识别，只是 main 只处理 1~8）。

## 硬件接线（普中 A2）

| 线 | 引脚 | 方向 | 说明 |
|:---|:---|:---|:---|
| 行线 | `P1.7 ~ P1.4` | 输入（读） | P1.7 = 第 1 行，P1.4 = 第 4 行 |
| 列线 | `P1.3 ~ P1.0` | 输出（扫描） | P1.3 = 第 1 列，P1.0 = 第 4 列 |
| LED | `P2.0 ~ P2.7` | 输出 | 低电平点亮，D1 ~ D8 依次对应 P2.0 ~ P2.7 |

按键编号（行优先，与 [[矩阵按键]] 笔记一致）：

```
第1行：S1  S2  S3  S4
第2行：S5  S6  S7  S8
第3行：S9  S10 S11 S12
第4行：S13 S14 S15 S16
```

> 16 个键为什么只要 8 根线：每个键跨在"一根行线 + 一根列线"的交叉点上，
> 4 行 × 4 列 = 16 个交叉点。按住哪个键，就把哪一行和哪一列短接在一起。

## 工程结构

```
矩阵键盘扫描/
├── User/main.c                 ← 应用层：只做调度（扫描 → 点灯）
├── Driver/
│   ├── MatrixKey_Scan.c/.h     ← 驱动层：扫描键盘，返回键号
│   └── LED.c/.h                ← 驱动层：P2 口点灯
├── System/
│   └── Delay.c/.h              ← 系统层：毫秒延时（消抖用）
├── Startup/STARTUP.A51
└── Project.uvproj              ← Keil 工程（User / Driver / System 三组）
```

调用方向：`main → MatrixKey_Scan → Delay`、`main → LED`。
**两个驱动之间不互相调用**——矩阵键盘不需要知道 LED 的存在，换个工程还能直接复用。

## 扫描原理：一列一列来

P1 口是"准双向口"：写 `0` 是强低电平，写 `1` 只是内部弱上拉。
所以让某一列输出 `0`，其余列输出 `1`，再读行线：

1. **第 1 列拉低**（`P1 = 0xF7`，只有 P1.3 = 0）；
2. 读 P1 高 4 位（行线）：
   - 全 `1`（`0xF0`）→ 这一列没有键按下；
   - 某一位变 `0` → 那一行的键被按下（键把该行短接到低电平的列上）；
3. 换下一列重复，直到 4 列扫完。

| 驱动的列 | P1 输出 | 读回 `0x70` | `0xB0` | `0xD0` | `0xE0` |
|:---|:---|:---:|:---:|:---:|:---:|
| 第 1 列（P1.3） | `0xF7` | S1 | S5 | S9 | S13 |
| 第 2 列（P1.2） | `0xFB` | S2 | S6 | S10 | S14 |
| 第 3 列（P1.1） | `0xFD` | S3 | S7 | S11 | S15 |
| 第 4 列（P1.0） | `0xFE` | S4 | S8 | S12 | S16 |

键号公式：**键号 = 行号 × 4 + 列号 + 1**（行、列都从 0 开始数）。

> 为什么一次只拉低一列：如果同时拉低多列，"行 × 列"的短接关系会互相串，
> 同时按下多个键时就可能读出一个根本没按的"鬼键"。一次一列，逻辑最简单。

## 关键代码逐段看

### 1. 逐列拉低

```c
KEYPAD_PORT = (unsigned char)~(0x01 << Col);   /* Col = 0,1,2,3 */
```

`0x01 << Col` 只让一位为 1，再取反就得到"只有这一位为 0"的值：
`0xF7 → 0xFB → 0xFD → 0xFE`，正好对应 P1.3 → P1.0。
强转 `(unsigned char)` 是因为 C 的整型提升会让 `~` 变成 16 位，避免高位干扰。

### 2. 只读高 4 位

```c
return (unsigned char)(KEYPAD_PORT & KEYPAD_ROW_MASK);   /* 0xF0 */
```

低 4 位是**我们自己刚输出的列电平**，读回来代表"我写了什么"，不能用来判断按键；
只有高 4 位（行线）才是被按键拉低的真实输入。

### 3. 消抖：读两次，中间等 10ms

```c
RowState = KeyPad_ReadRow();
if (RowState == KEYPAD_ROW_MASK) continue;   /* 第一次就没键，跳过 */

Delay_ms(10);
RowState = KeyPad_ReadRow();
if (RowState == KEYPAD_ROW_MASK) continue;   /* 10ms 后松了：是抖动，不算 */
```

机械按键按下/松开瞬间会抖动 5 ~ 20ms，只读一次会误判成"按了好几次"。
所以第一次读到低先别急着报，等抖动过去再确认一次。

### 4. 行号换算 + 键号

```c
static unsigned char KeyPad_RowToIndex(unsigned char RowState)
{
    if ((RowState & 0x80) == 0) return 0;   /* P1.7 被拉低 = 第 1 行 */
    if ((RowState & 0x40) == 0) return 1;
    if ((RowState & 0x20) == 0) return 2;
    return 3;
}
```

从 P1.7 往下找第一个 `0`，就是被拉低的哪一行。
最后 `KeyNum = 行 × 4 + 列 + 1`，得到 1 ~ 16。

### 5. 扫完把端口放回高电平

```c
KEYPAD_PORT = 0xFF;
```

否则最后一列会一直保持低电平：长按某个键时，那一列对地一直导通，白白耗电，
也容易让后面的代码误以为端口处于"正在扫描"的状态。

### 6. 为什么"按住一直返回，松开返回 0"

`main` 的循环每一轮都调用一次 `MatrixKey_Scan()`：

- 按住时返回键号 → `LED_OnOne(KeyNum - 1)` 点亮；
- 松开时返回 `0` → `LED_AllOff()` 熄灭。

驱动里**没有** `while (键还按着);` 这样的等待。原因：
1. 等待松开会让主循环卡在驱动里，别的活（以后加定时器、显示刷新）都干不了；
2. "按住亮、松开灭"这个效果本来就需要每轮都知道当前状态，而不是只在"松开的瞬间"报一次。

这也是后面做"松手触发 / 长按 / 连按"的基础：要哪种行为，由 `main` 根据返回值决定，
驱动只负责如实报告"现在按的是哪个键"。

## 原稿踩过的坑（对照学习）

| # | 原稿写法 | 问题 | 正确做法 |
|:--:|:---|:---|:---|
| 1 | `if ((P1 & 0x0F != 0x0F))` | `!=` 优先级高于 `&`，实际等于 `P1 & 0`，恒为假 → 永远检测不到按键 | `if ((P1 & 0x0F) != 0x0F)`，括号不能省 |
| 2 | 注释写"列 P1.0~P1.3"、代码却驱动 P1.7 | 行/列掩码写反（`ROW_MASK=0x0F`） | 列在低 4 位 `0x0F`、行在高 4 位 `0xF0` |
| 3 | 调用 `Delay_ms(10)` 却没 `#include "Delay.h"` | C51 隐式声明，链接时可能找不到或参数类型不符 | 在 `.c` 里包含 `Delay.h`，在 `.h` 里声明对外函数 |
| 4 | `while ((P1 & 0x0F) != 0x0F);` 等松开 | 与"按住点亮"矛盾，还会卡住主循环 | 不等待，直接返回键号，由 main 决定怎么用 |
| 5 | `Driver/Delay_ms.c` 和 `System/Delay.c` 都定义 `Delay_ms` | 同名函数重复定义，链接报错 | 只保留 `System/Delay.c`，删掉驱动里的临时版本 |
| 6 | 函数没在 `.h` 里声明 | `main.c` 调用时编译告警/报错 | `.h` 先写"菜单"（宏 + 函数声明），`.c` 再写实现 |

> 第 1 条和第 4 条其实都是同一个思维习惯：**写条件时先想优先级，写循环时先想会不会卡死**。
> 这和《按键》笔记里 `x = P2` 的坑是一类问题。

## 排错清单

| 现象 | 先查什么 |
|:---|:---|
| 一个灯都不亮 | 矩阵键盘是否插在 P1 口；P1 是否被 NRF24L01 / 步进电机模块占用（三者共用 P1，不能同时插） |
| 按键和灯对不上 | 行列定义是否与板子一致：P1.7 第 1 行、P1.3 第 1 列；或按键排线插反 |
| 按一下亮好几下 | 消抖时间太短（把 `KEYPAD_DEBOUNCE_MS` 调到 10~20ms） |
| 松开还亮着 | 端口最后有没有恢复 `0xFF`；或 `main` 的 `else` 分支没调用 `LED_AllOff()` |
| 编译报 `can't open file 'REGX52.H'` | Keil 的 C51 Include Paths 要有 `D:\APP\Keil\C51\INC` 和 `...\INC\Atmel` |
