# 单片机C编程地基

> 这不是教你 C 语言，而是教"标准 C 和单片机之间那层**通用C里没有翻译**"。你 `03_编程与工具/C语言` 那套学的是电脑编程，而这一篇是搞懂 `P2 = 0x00` 到底发生了什么。**这篇地基能同时服务：51 学顺 → 转 STM32 → 蓝桥杯单片机组。**

---

## 0. 一句话抓住核心

**普通电脑 C：变量在内存里，程序在操作系统里跑。**
**单片机 C：没有操作系统，变量就是寄存器，写代码 = 直接操作硬件地址。**

所以单片机编程的**全部秘密**就是：怎么让一段 C 代码，去控制一块真实存在的硬件（引脚、定时器、串口）。这就是 `sbit`、`sfr`、位运算、存储类型存在的意义。

---

## 1. 寄存器直操原理：`P2 = 0x00` 到底发生了什么

### 1.1 你踩过的坑（最有价值）

你在按键初版代码里写过这个，后来废弃了：

```c
unsigned char x = P2;   // ❌ x 只是拷贝了 P2 的值存到 RAM
x = 0x00;               // ❌ 改 x 不影响硬件引脚，灯不会亮
```

| 错误写法 | 正确写法 |
|:---|:---|
| `unsigned char x = P2; x = 0x00;` ❌ | `P2 = 0x00;` ✅ |
| 操作的是 RAM 里的普通变量 | 操作的是地址 `0xA0` 的硬件寄存器 |

### 1.2 为什么 P2 不是普通变量

普中 A2（STC89C52RC）上，**P2 端口对应芯片内部一个物理地址 `0xA0`**。在硬件层面，这个地址连接着 8 根真实的引脚（P2.0~P2.7）。

- `P2 = 0x00;` = 往地址 `0xA0` 写入，芯片硬件立刻把 8 根引脚拉到低电平
- 这不是"存了个值"，是**驱动真实电压变化**，所以灯亮

### 1.3 用指针理解（把通用 C 的指针用起来！）

你 C 语言笔记里学的指针，在这里派上真正用途了：

```c
// 这两行完全等价：
P2 = 0xFE;
*(unsigned char *)0xA0 = 0xFE;   // 把地址0xA0当unsigned char指针，赋0xFE
```

> 💡 这就是为什么头文件重要：没有 `REGX52.H`，你每次都要写 `*(unsigned char *)0xA0`，烦死。有了 `#define P2 (*(volatile unsigned char *)0xA0)`，直接写 `P2` 就行了。（`volatile` 是告诉编译器"这个地址会被硬件改，别优化掉"，后续 STM32 也会见到）

**核心认知**：`P2` 是硬件寄存器的"别名"，不是普通变量。普通变量在 RAM，寄存器在芯片内部有真实地址和硬件行为。

## 2. `sfr` 与 `sbit`：给寄存器和引脚起名字

### 2.1 `sfr`（Special Function Register）— 字节级

`sfr` 把"8位特殊功能寄存器"的物理地址映射成 C 变量名：

```c
sfr P0 = 0x80;   // P0端口的地址是0x80
sfr P2 = 0xA0;   // P2端口的地址是0xA0
sfr P3 = 0xB0;   // P3端口的地址是0xB0
```

这一行 `sfr P2 = 0xA0;` 就是告诉你：**"以后写 P2，就是操作 0xA0 这个硬件地址"**。

### 2.2 `sbit`（Single Bit）— 位级

在 51 里，某些特殊寄存器**支持按位寻址**（单个 bit 可单独读写）。`sbit` 把一个 bit 映射成名字：

```c
sbit LED1 = P2^0;   // P2寄存器第0位 → 起名LED1
sbit LED2 = P2^1;
sbit KEY1 = P3^1;   // 按键引脚（普中A2：K1接P3.1，官方 KEY1=P3^1）
```

你早期的 LED 实验就是这么用的：
```c
sbit LED1 = P2^0;   // 定义位变量
LED1 = 0;           // 把P2.0拉低 → 点亮单独一个LED
```

### 2.3 sbit 和普通 C 里 `struct{...}` 里那种"位域"的不同

| 对比 | 通用 C 位域 | 51 的 sbit |
|:---|:---|:---|
| 归属 | struct 内的字段 | 芯片硬件上的真实引脚/寄存器位 |
| 地址 | 编译时分配 | 固定对应物理地址 |
| 写它 | 改内存 | 直接控制引脚电平 |

> 关键：**sbit 起的名字，本质上是一个"钉死"在硬件地址上的别名**，不是普通 C 的变量。

## 3. 位运算实战：怎么点某一盏灯 / 关某一位

这是单片机最常用的技能。`LED_PORT = P2` 是 8 盏灯，怎么**只动其中一盏**、不影响其他？

### 3.1 点某一盏灯（置 0，因为低电平点亮）

```c
P2 = P2 & 0xFE;      // 只把第0位置0，其他位不动。0xFE = 1111 1110
L1 亮，L2~L8 保持原状
```

- `&` 按位与：任何位 `& 0` 都会变 0，`& 1` 保持不变
- 想灭第0位（置零）：`P2 &= 0xFE;`

### 3.2 关某一盏灯（置 1）

```c
P2 = P2 | 0x01;      // 只把第0位置1。0x01 = 0000 0001
```

- `|` 按位或：任何位 `| 1` 都会变 1，`| 0` 保持不变

### 3.3 反转某一盏灯（取反）

```c
P2 = P2 ^ 0x01;      // 第0位取反（0变1,1变0），其他不动。^ = 按位异或
```

### 3.4 口诀表（结合你灯是"0亮1灭"）

| 想干什么 | 操作 | 例子 |
|:---|:---|:---|
| 点亮第 n 位 | `P2 &= ~(1 << n);` | `P2 &= ~(1<<3);` 点亮D4 |
| 熄灭第 n 位 | `P2 |= (1 << n);` | `P2 |= (1<<3);` 熄灭D4 |
| 翻转第 n 位 | `P2 ^= (1 << n);` | `P2 ^= (1<<3);` 翻转D4 |
| 同时亮第一盏 | `P2 = 0xFE;` | 1111 1110 |

> 你流水灯的 `0xFE`（1111 1110）和 `_crol_` 循环移位，本质都是在做"位图案"的位移运算，只是换了个写法。这块接上 [[LED]] 的 6 大位运算就是一套完整的。

> ⭐ **踩坑提醒**：不要用 `P2 |= ~0x01;` 这种让人眼晕的写法，`~(1<<n)` / `(1<<n)` 最直观、不容易错。

## 4. 存储类型：`data` / `idata` / `code` / `xdata`（这块你笔记里没有）

这是 **51 和普通 C 最大的不同之一** —— 51 的 RAM 极小且分片，得手动告诉编译器把变量放哪。

### 4.1 51 的三种 RAM + 一种 ROM

| 关键字 | 存哪 | 大小 | 特点 | 使用 |
|:---|:---|:---|:---|:---|
| `data` | 片内RAM低128B（0x00~0x7F） | 128B | 最快，但极小 | 常用变量、循环计数 |
| `idata` | 片内RAM（含高128B） | 256B | 间接寻址，快 | 变量多时扩展 |
| `xdata` | 外部RAM | 64KB | 慢，要走总线 | 大数组、缓冲区 |
| `code` | 程序存储区（Flash） | 大 | 只读，烧进Flash | **常量表**、查找表 |

### 4.2 最实用的是 `code`：把表存进 ROM

你写按键扫描、数码管段码，会有**常量表**。默认放 RAM 会浪费珍贵内存：

```c
// ❌ 默认放RAM，浪费128B里的小空间
unsigned char seg[] = {0xC0,0xF9,0xA4,...};

// ✅ 用code放进Flash，不占RAM，程序跑起来就能用
code unsigned char seg[] = {0xC0,0xF9,0xA4,0xB0,0x99,0x92,0x82,0xF8};
```

> 以后学 `xdata` 数组、`pdata` 时再细说，现在你只要知道：**RAM 很珍贵，常量数组用 `code` 存**。

### 4.3 为什么 51 要手动分这些

因为它 RAM 一共才 256 字节，一个 51 程序如果不规划存储，大数组一放就爆了。普通电脑 C 你不用管，因为内存根本用不完。这是**资源受限嵌入式**的入门感受。

## 5. `REGX52.H` 头文件解构：它到底帮你做了啥

你在 [[工具库]] 已经看过对比，这里从"地基"角度串一遍：

```c
// REGX52.H / reg52.h 里，核心就干两件事：

// ① 定义所有特殊功能寄存器（sfr）
sfr P0 = 0x80;  sfr P1 = 0x90;
sfr P2 = 0xA0;  sfr P3 = 0xB0;
sfr TMOD = 0x89; sfr TCON = 0x88;   // 定时器控制
sfr SCON = 0x98; sfr SBUF = 0x99;   // 串口控制

// ② 定义可位寻址的位（sbit）
sbit P2_0 = P2^0;
sbit TR0 = 0x8C;   // 定时器0运行控制位
```

**它存在的意义**：让你不用写 `*(unsigned char *)0xA0`，直接 `P2`、`TMOD`、`SBUF` 就能操作硬件。**你以后学定时器、串口，其实就是去操作这些头文件里定义好的寄存器。**

> 后续章节预告：定时器 → 操作 `TMOD/TCON/TH0/TL0`；串口 → 操作 `SCON/SBUF`。这些"新知识"拆穿了，全是"往对应寄存器写特定值"。

## 6. 指针对寄存器访问（把通用 C 彻底打通）

普通 C 你学了指针。在嵌入式里，**指针的最大用处之一就是直接操作硬件地址**。

```c
// 用指针直接访问寄存器（理解用，实际不用这么写）
#define REG_P2  (*(volatile unsigned char *)0xA0)

REG_P2 = 0xFE;        // 等价于 P2 = 0xFE;
```

- `(unsigned char *)0xA0`：把地址0xA0转成指针
- `*` 解引用：读写这块内存
- `volatile`：防止编译器优化掉对硬件的读写

> 这在**STM32 的寄存器开发模式**里会大量用到（像 `*(volatile uint32_t *)0x40021000 = value` 就是 STM32 的寄存器代码）。你在 51 提前理解了这个，转 STM32 时 `寄存器操作` 那套一看就懂，不需要重新学。

## 7. 延时原理：为什么单片机要"空转"

你的延时函数（见 [[工具库]]）本质是**让 CPU 空跑循环，消耗时间**：

```c
void delay_10us(u16 ten_us)
{
    while(ten_us--);   // CPU 在这里空转，什么都不干，只为耗时间
}
```

**为什么需要**：
- CPU 一条指令约 1 微秒，太快
- 要让灯"亮一会儿"，就得让 CPU 停下来等 → 软件延时
- 但软件延时**不精确**（和晶振、编译器优化有关），精确计时要用**定时器**（这是你下一个要学的）

> 为什么 51 需要延时：人眼视觉暂留约 24ms（攻略口径），切换太快你会看到"微微亮"而不是闪烁。见 [[LED]] 实验二。

## 8. 铺垫中断思想（下一步的钥匙）

定时器、串口、按键的进阶玩法都建立在**中断**上。先建立概念：

- **轮询（你现在的做法）**：主循环一直盯着"按键按了吗？""时间到了吗？"——像店员一直盯着门口
- **中断（更高级）**：让主程序干别的，硬件一触发就"打断"主程序去处理，处理完再回来——像店员忙自己的，门铃响了才去开门

```
中断执行流程：
CPU在干主程序 → 硬件事件来(门铃) → 暂停主程序 → 跳到中断服务函数
→ 处理完 → 回到主程序接着干
```

51 的中断服务函数写法（先看一眼）：
```c
void Timer0_ISR() interrupt 1   // interrupt 1 = 定时器0中断号
{
    // 中断里要做的（比如翻转灯）
}
```

> 你现在知道"有中断这回事、它是干嘛的"就够，等学定时器/串口时再深入。地基先铺到这一层。
