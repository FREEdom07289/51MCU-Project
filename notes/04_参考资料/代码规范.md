# 代码规范 — 江科大模块化风格（项目执行版）

> **适用范围**：C51 / STM32（Keil MDK、STM32CubeIDE）；课程作业、实验报告、蓝桥杯、智能车、个人项目通用。
> **怎么用**：新工程 → §2 结构 + §3 模板；写函数 → §4 注释；中断 / 串口 → §5 / §6；编译报错 → §7；提交前 → §8 清单。
> **核心思想**：分文件说明 + 函数头注释 + 关键行精简注释；只写"为什么这么写"，不堆废话。
> **与旧版关系**：本版在 V1.4 基础上重排结构、合并重复、补齐缺口、修正技术错误，要求未放宽。改动清单见 §10。

## 0. 速查

### 0.1 五条硬规则（违反任何一条即为不合格）

| # | 规则 | 典型违反 |
|:--:|:---|:---|
| 1 | 一个硬件 / 一件独立的事 = 一对同名 `.c/.h`；**函数不是模块** | 一个函数建一个文件，或十几个模块全塞 `main.c` |
| 2 | 依赖单向：**驱动不得调用其他驱动**（可调用 System）；`main` 只做调度 | `LCD1602.c` 里调用 `KEY_Scan()` |
| 3 | `main.c` 里**不出现引脚名、寄存器名、魔法延时** | `P2_5 = 1;`、`TMOD = 0x01;`、`Delay(500);` |
| 4 | 中断只置标志，**主循环干活**；跨中断共享变量必须 `volatile` | 中断里 `Delay()`、刷新 LCD、打印串口 |
| 5 | 函数括号里不是 `void`，**就必须有 `@param`**；提交前过 §8 清单 | 3 个参数只写 2 行 `@param` |

### 0.2 场景速查

| 我要做什么 | 看哪一节 | 关键动作 |
|:---|:---|:---|
| 新建一个工程 | §2.3、§2.5 | 先列硬件清单，再建 `User/Driver/System` |
| 新建一个模块 | §3.1、§3.2 | 先写 `.h` 定菜单，再写 `.c` 填实现 |
| 写主程序 | §3.4 | 只写流程，不碰引脚 |
| 写函数注释 | §4.3 | 套模板，数逗号核对 `@param` 行数 |
| 注释宏 / 全局变量 | §4.4 | 右侧一句话：是什么 + 单位 / 范围 |
| 写中断 | §5 | 签名 `void xxx(void)`，只置标志 |
| 写串口 | §6 | 文件头写全通信参数，`putchar` 提醒 MicroLIB |
| 编译 / 链接报错 | §7.1 | 检查 `.c` 是否 Add、Include Paths 是否全 |
| 提交作业 / 实验报告 | §8 | 逐条打勾，改 `@author` 为真名 |
| 照抄示例前核对引脚 | §9 | 普中 A2 的实际引脚与示例占位可能不同 |

## 1. 全局统一约定

### 1.1 排版与编码

| 项目 | 规则 | 说明 |
|:---|:---|:---|
| 缩进 | 4 个空格，禁止 Tab | Keil：`Edit → Configuration → Editor` 设 Tab Size 4，取消 Insert Tab |
| 花括号 | 左括号不换行（K&R），**单行也必须加** | 禁止 `if (x) y = 1;` |
| 编码 | **UTF-8（无 BOM）**，禁止 GB2312 / UTF-8 混存 | 本机实测：桌面 Keil 工程中含中文的 32 个 `.c/.h` 全部为 UTF-8 无 BOM（另 1 个纯 ASCII），工具链为 Keil MDK 5.42 + C51（`D:\APP\Keil`）。VS Code 右下角选 UTF-8；Keil 在 `Edit → Configuration → Editor → Encoding` 选 UTF-8。切勿用记事本或 Keil 另存为 ANSI，转码后中文注释必乱码 |
| 注释语言 | 全项目中文；I2C、CRC、SPI 等专有名词保留英文 | — |
| 语句 | 一行一条语句 | 便于断点与单步 |
| 空行 | 函数之间空一行，分区之间空一行 | 与 §3.2 的分区线配合 |

### 1.2 命名

| 对象 | 规则 | 示例 |
|:---|:---|:---|
| 文件名 | 模块名大驼峰，`.c` / `.h` 同名成对 | `LCD1602.c` / `LCD1602.h` |
| 公开函数 | `模块名_动作`，动作用大驼峰 | `LCD1602_ShowString()` |
| 私有函数 | 加 `static`，前缀可选 `_` | `static void BEEP_Toggle(void)` |
| 普通变量 | 小驼峰或小写下划线，**全项目二选一** | `alarmFlag` / `alarm_flag` |
| 标志位 | 后缀 `Flag` | `Key_Flag` |
| 计数器 | 后缀 `Cnt` | `Timer_Cnt` |
| 常量宏 | 全大写下划线 | `BEEP_FREQ` |
| 带单位的常量 | 建议把单位写进名字（非强制，选了就统一） | `KEY_SCAN_PERIOD_MS` |
| 结构体 | 后缀 `_t` | `Time_t` |
| 枚举 | 后缀 `_e`，成员全大写 | `State_e` / `STATE_IDLE` |

**禁止**：中文变量名、中文函数名、拼音缩写、单字母全局变量（循环变量 `i` / `j` 除外）。

### 1.3 作者署名（`@author` 按场合切换，不要混用）

| 代码用途 | `@author` 写法 | 原因 |
|:---|:---|:---|
| 个人项目、GitHub、笔记库、竞赛提交 | `@author FREEDOM` | 个人代号，跨项目长期可追溯 |
| **课程作业、实验报告**（交给老师或助教） | `@author 詹诗意` | 必须写真名，老师按姓名学号核对，代号对不上人 |
| 一份代码同时用于以上两类 | `@author FREEDOM（詹诗意）` | 括号内为学籍真名，兼顾标识与核验 |

> 实操：同一工程从"个人项目"改成"作业提交"时，**只批量替换 `@author` 那一行**，逻辑不动——作者信息单独占一行的意义就在这里。

### 1.4 版本与修改记录

- 每个 `.c/.h` 文件头写 `@version`（如 `V1.0`）。
- 每次改动在 `@note` 的"修改记录"里追加一行，格式固定：`V1.x 日期 改动摘要`。
- 只追加、不删旧行；版本号与代码实际状态一致，不做"改了不升版"。

### 1.5 禁止留在代码里的东西

1. 调试用的 `printf`。
2. 临时的 `// xxx 测试` 注释。
3. 被注释掉的大段废弃代码（用 git 回溯，不要留在文件里）。

## 2. 工程结构与模块划分

### 2.1 三层模型与调用方向

| 层 | 对应文件 | 类比 | 谁调用它 | 里面写什么 |
|:---|:---|:---|:---|:---|
| **驱动层** | `LED.c`、`KEY.c`、`LCD1602.c` | 后厨的菜谱 | 只被 `main` 调用 | 直接操作寄存器 / 引脚，只管一件事怎么做 |
| **系统层** | `Delay.c`、`Timer.c`、`UART.c` | 厨房的水电煤 | 被各层调用 | 通用工具：延时、定时中断、串口 |
| **应用层** | `main.c` | 顾客点单 | 没人调它 | 决定先做什么、后做什么、满足什么条件才做什么 |

```
main.c（应用层）
  ├──→ Driver/*.c（LED / KEY / LCD1602 / DS1302 …）
  └──→ System/*.c（Delay / Timer / UART …）
             ▲
Driver/*.c ──┘  只能向下调 System
```

### 2.2 依赖铁律

1. **驱动可以调用 System**（如 `BEEP.c` 调 `Delay()`），但**不得横向调用另一个驱动**。
2. **System 不得反向依赖驱动**（`Delay.c` 里不出现 `LCD1602_ShowString()`）。
3. **`main` 调用所有模块**，负责顺序与条件。
4. 判断依据：若 `LCD1602.c` 去调 `KEY.c`，等于"菜谱去指挥顾客按按钮"；日后想把 LCD 复用到另一个工程，会发现它牵连了 KEY，拆不走——这就是模块化崩坏的起点。

> 前面说"驱动不能调用驱动"是省略说法，完整规则是：**驱动只能依赖 System 和自身，不能依赖平级驱动。**

### 2.3 标准目录树（江科大经典划分）

```
Project
├── User                  // 主程序
│   └── main.c
├── Driver                // 外设驱动，一个外设一对 .c/.h
│   ├── LCD1602.c / LCD1602.h
│   ├── BEEP.c    / BEEP.h
│   ├── KEY.c     / KEY.h
│   └── DS1302.c  / DS1302.h
├── System                // 系统级：延时、定时器、中断、串口
│   ├── Delay.c   / Delay.h
│   ├── Timer.c   / Timer.h
│   └── UART.c    / UART.h
└── Hardware              // 板级硬件初始化（可选）
    └── Board.c   / Board.h
```

### 2.4 模块粒度：一个硬件 / 一件事 = 一个 `.c`

**函数不是模块，`.c` 文件才是模块。** 一个 `.c` 里可以有 3 个、5 个、10 个函数，只要它们服务于同一件事（同一个硬件 / 同一个主题）。

- ✅ `BEEP.c` 里放 `BEEP_ON` / `BEEP_OFF` / `BEEP_Beep` / `BEEP_Toggle`。
- ❌ 一个函数建一个文件；也 ❌ 十几个不相干的功能全塞 `main.c`。

### 2.5 开工顺序（不要一上来就写 main）

```
第 1 步：列清单       → 这套程序要用到哪些硬件？（先纸笔列出来）
第 2 步：建目录建文件  → 每个硬件建一对 .c/.h
第 3 步：先写 .h      → 定"菜单"：对外提供哪些函数、用哪些引脚
第 4 步：再写 .c      → 填"后厨"：函数的具体实现
第 5 步：最后写 main  → 只写流程，按顺序调用
```

以"寝室提醒器"为例，清单是 LCD1602、蜂鸣器、DS1302、按键、延时，则建：

```
Project/
├── User/main.c
├── Driver/LCD1602.c + LCD1602.h
├── Driver/BEEP.c    + BEEP.h
├── Driver/DS1302.c  + DS1302.h
├── Driver/KEY.c     + KEY.h
└── System/Delay.c   + Delay.h
```

七对文件里 **`main.c` 只有 1 个**，其余 6 对都是"现成的菜谱"，用时只取所需。

### 2.6 函数归位三问

写完一个函数不知道往哪塞，按顺序问三个问题：

| 问题 | 是 | 否 |
|:---|:---|:---|
| 1. 它直接碰寄存器 / 引脚吗？ | → 对应硬件的模块 | 往下问 |
| 2. 它是纯工具（延时、转码、求平均）？ | → `Delay.c` 或 `System.c` | 往下问 |
| 3. 它在协调多个模块、决定顺序？ | → `main.c` | 说明它属于某个模块，回头想它服务谁 |

按这三条：`KEY_Scan` → `KEY.c`；`BEEP_Beep` → `BEEP.c`；`Delay` → `Delay.c`；`Alarm_Flag` 置位 → `main.c`。不会再出现"放哪儿都行"的纠结。

### 2.7 模块化验收标准

> **别人把你的 `main.c` 拿走、换成他自己写的主流程，你那些驱动文件还能原样拿去用——这就是模块化成功了。**

且满足：`main.c` 里一个 `P2_5 = 1`、一个 `TMOD = 0x01`、一个 `Delay(500)` 都没有（`Delay()` 本身可以调，但不该由 main 直接决定阻塞时长）。

### 2.8 跨文件共享：`extern` 与 `code` 表

| 场景 | `.h` 里写 | `.c` 里写 |
|:---|:---|:---|
| 共享变量 | `extern unsigned char Alarm_Flag;` | `unsigned char Alarm_Flag = 0;` |
| 共享常量表（省 RAM） | `extern code unsigned char SEG_CODE[10];` | `code unsigned char SEG_CODE[10] = {0x3F, ...};` |

规则：

1. **变量 / 数组的定义只能出现一次，放 `.c`；`.h` 只放 `extern` 声明。**
2. 在 `.h` 里写定义，会被多个 `.c` 包含，链接时报 `MULTIPLE PUBLIC DEFINITIONS`（L104）。
3. `sbit` 在 C51 里是**定义**，不是声明，不能放公共 `.h`，否则多个 `.c` 包含后报 `sbit` 重复定义。
4. 51 上大数组加 `code` 放 Flash，否则占 RAM（STC89C52RC 只有 512B）。

### 2.9 `.h` 与 `.c` 的职责

| 文件 | 放什么 | 不放什么 |
|:---|:---|:---|
| `.h`（菜单） | 对外宏 / 引脚定义、类型、函数声明、`extern` 声明 | 函数实现、变量定义、`sbit` 定义 |
| `.c`（后厨） | 函数实现、`static` 私有变量、私有函数、`sbit` 定义、`code` 表定义 | 对外接口的重复声明 |

依赖的 `.h` 尽量在 `.c` 里 `#include`，不对外暴露内部依赖：

```c
/* BEEP.h —— 不写 #include "Delay.h" */
void BEEP_Beep(unsigned int ms);

/* BEEP.c —— 只有实现需要延时，依赖不暴露给 main */
#include "BEEP.h"
#include "Delay.h"
```

> 例外：若 `.h` 里声明的接口用到了其他头文件的类型（如 `u8`、自定义结构体），该类型头**必须**在 `.h` 中包含，否则包含者编译不过。原则是"只暴露接口必需的类型"，不是盲目禁止 include。

## 3. 文件模板

### 3.1 `xxx.h` 模板

```c
#ifndef __BEEP_H
#define __BEEP_H

#include <REGX52.H>

/* ==================== 对外引脚定义 ==================== */

#define BEEP_PIN    P2_5      /* 普中A2：P2.5 经 ULN2003D 反相驱动，1=响 */

/* ==================== 对外接口声明 ==================== */

void BEEP_ON(void);
void BEEP_OFF(void);
void BEEP_Beep(unsigned int ms);   /* C51 无 uint16_t，统一用 unsigned int */

/* ==================== 对外共享变量（只声明，不定义） ==================== */

extern unsigned char BEEP_Count;

#endif
```

### 3.2 `xxx.c` 模板

```c
/**
 * @file    BEEP.c
 * @brief   蜂鸣器驱动模块，提供开、关、定时鸣叫功能
 * @author  FREEDOM
 * @version V1.0
 * @date    2026-11-11
 * @note    硬件引脚：P2.5（普中A2，ULN2003D 反相，1=响；无源蜂鸣器需方波驱动）
 *          依赖模块：Delay.c（提供毫秒延时）
 *          修改记录：
 *            V1.0 2026-11-11 初版，实现基础鸣叫
 */
#include <REGX52.H>
#include "BEEP.h"
#include "Delay.h"

/* ==================== 私有宏与变量 ==================== */

#define BEEP_FREQ 1000      /* 鸣叫频率，单位 Hz */

static unsigned char beep_flag = 0;

/* ==================== 私有函数声明 ==================== */

static void BEEP_Toggle(void);

/* ==================== 对外接口实现 ==================== */

void BEEP_ON(void)
{
    BEEP_PIN = 1;           /* ULN2003D 反相后导通，蜂鸣器得电 */
}

void BEEP_OFF(void)
{
    BEEP_PIN = 0;
}

/**
 * @brief  蜂鸣器鸣叫指定时长
 * @param  ms 鸣叫时长，单位毫秒，建议 50 ~ 500（超过 1000 会明显卡住主循环）
 * @retval None
 * @note   每 1ms 翻转一次，约 500Hz；内部调用 Delay()，会阻塞主循环，勿在中断中调用
 */
void BEEP_Beep(unsigned int ms)
{
    unsigned int i;

    for (i = 0; i < ms; i++)
    {
        BEEP_Toggle();
        Delay(1);
    }
    BEEP_OFF();             /* 结束确保关闭 */
}

/* ==================== 私有函数实现 ==================== */

static void BEEP_Toggle(void)
{
    BEEP_PIN = !BEEP_PIN;
}
```

> 无源蜂鸣器必须给方波才会响，仅置高电平不发声；有源蜂鸣器才会"通电即响"。本库开发板为无源型，具体音调与引脚见 [[蜂鸣器]]。

### 3.3 `.c` 内部固定顺序

每个 `.c` 从上到下固定九段，不要随意调换：

```
① 文件头注释块
② #include <系统头>          ← 先系统
③ #include "自己的.h"         ← 再自己
④ #include "依赖的其他.h"      ← 再依赖
⑤ #define 私有宏
⑥ static 私有变量
⑦ static 私有函数声明
⑧ 对外接口实现（给 main 用的）
⑨ 私有函数实现（只给自己用的）
```

`main.c` 例外：**`main()` 紧跟全局变量放在最上面**，辅助函数放它下面，打开文件一眼能看到主流程。

### 3.4 `main.c` 模板

```c
/**
 * @file    main.c
 * @brief   寝室值日提醒器主程序：LCD 显示时间，定点蜂鸣提醒
 * @author  FREEDOM
 * @version V1.0
 * @date    2026-11-11
 * @note    硬件：STC89C52 + LCD1602 + 无源蜂鸣器 + DS1302 时钟
 *          引脚以实际板子为准（见 §9）；普中A2 上 LCD 控制口与蜂鸣器共用 P2.5，
 *          不能同时使用，需按实际接线调整引脚或分时复用
 *          修改记录：
 *            V1.0 2026-11-11 初版
 */
#include <REGX52.H>
#include "Delay.h"
#include "LCD1602.h"
#include "DS1302.h"
#include "BEEP.h"

/* ==================== 全局变量 ==================== */

unsigned char Alarm_Hour = 20;      /* 闹钟小时，范围 0~23 */
unsigned char Alarm_Min  = 30;      /* 闹钟分钟，范围 0~59 */
bit           Alarm_Flag = 0;       /* 1 表示已到点，待处理 */

/* ==================== 主函数 ==================== */

void main(void)
{
    /* 外设初始化，先时钟后显示 */
    LCD1602_Init();
    DS1302_Init();
    BEEP_OFF();

    while (1)
    {
        DS1302_ReadTime();                  /* 读取当前时间 */
        LCD1602_ShowTime();                 /* 刷新屏幕 */

        if (DS1302_Time[2] == Alarm_Hour && DS1302_Time[1] == Alarm_Min)
        {
            Alarm_Flag = 1;                 /* 到点置位，交由主循环处理 */
        }

        if (Alarm_Flag)
        {
            BEEP_Beep(200);                 /* 响 200ms */
            Alarm_Flag = 0;                 /* 单次提醒，清除标志 */
        }
    }
}
```

> 判断模块化是否写对：**`main.c` 里出现引脚名、寄存器名、`Delay(500)` 这类魔法延时，就说明该逻辑还留在 main 里。**

### 3.5 模板落地检查

- [ ] `.c` / `.h` 同名成对，模块名与目录一致
- [ ] `.h` 有 `#ifndef` 卫士，且只放声明
- [ ] `.c` 按 §3.3 的九段顺序组织
- [ ] 每个 `.c` 都已 Add 进 Keil 工程（见 §7.1）
- [ ] `main.c` 只有流程，没有引脚 / 寄存器操作

## 4. 注释规范

### 4.1 注释的边界：只写"为什么"，不写"是什么"

反面例子（废话注释，一律禁止）：

```c
i++;            // i 自增
Delay(10);      // 延时 10ms
P2_5 = 1;       // P2.5 置 1
```

正面例子（合法注释）：

```c
i++;            // 跳过数组第 0 位校验位
Delay(10);      // 等待 LCD 内部指令执行完成，手册要求 > 5ms
P2_5 = 1;       // ULN2003D 反相后导通，蜂鸣器得电
```

**必须加注释的场合**

| 场合 | 说明 |
|:---|:---|
| 硬件时序 | 延时、电平翻转、时钟沿的原因 |
| 特殊算法 | CRC 校验、滤波、查表、位运算技巧 |
| 魔法数字 | 出现非 0/1 的字面量时说明来历 |
| 易错点 | 写反会出 bug 的地方，防止后人踩坑 |
| TODO / FIXME | 未完成或已知缺陷，格式 `// TODO: xxx` |
| 大段代码起始 | 循环或分支块的意义 |

**不必加注释的场合**

- 简单赋值、自增、条件判断
- 函数名已能完整表意的调用
- 与上方函数注释重复的说明

### 4.2 文件头注释

每个 `.c` / `.h` 文件最顶部必须有注释块，字段如下：

| 字段 | 必填 | 内容要求 |
|:---|:---:|:---|
| `@file` | ✅ | 文件名，如 `BEEP.c` |
| `@brief` | ✅ | 一句话说清模块职责（动词 / 名词短语） |
| `@author` | ✅ | 按 §1.3 的场合规则 |
| `@version` | ✅ | 当前版本，如 `V1.0` |
| `@date` | ✅ | 创建 / 最后修改日期 |
| `@note` | ✅ | 硬件引脚、依赖模块、通信参数、限制条件、修改记录；至少写引脚与依赖 |

完整示例见 §3.2；串口模块的 `@note` 还须多写通信参数，见 §6.2。

### 4.3 函数注释

#### 4.3.1 标准模板

```c
/**
 * @brief  函数简短功能描述（一句话，动词开头）
 * @param  参数名 含义、单位、取值范围（一个参数一行，顺序同函数定义）
 * @retval 返回值说明；无返回值写 None
 * @note   可选：使用前提、限制条件、副作用
 */
void FunctionName(unsigned char para)
{

}
```

#### 4.3.2 `@param` 四条硬规则

| 规则 | 说明 |
|:---|:---|
| 1 | **一个参数一行**，函数有几个参数就写几行 `@param` |
| 2 | **顺序必须与函数定义中的参数顺序完全一致**，不能颠倒、不能漏中间那个 |
| 3 | **无参数的函数，整行 `@param` 都不写**——不要写 `@param None`，也不要写 `@param 无` |
| 4 | 参数名必须与定义**逐字一致**，不能翻译成中文、不能缩写 |

#### 4.3.3 参数写什么：三要素

**是什么 → 取值范围 → 单位 / 边界**，三者缺一不可。

| 写法 | 评价 |
|:---|:---|
| `@param ms 毫秒` | ❌ 只说了单位，等于没说 |
| `@param ms 时间` | ❌ 废话，调用者仍不知能传多少 |
| `@param ms 鸣叫时长，单位毫秒，建议 50 ~ 500` | ✅ 三要素齐全 |

为什么要写范围：调用者看函数名只知道"能传一个数"，不知道该传 10 还是 10000。不写清楚，他只能去翻 `.c` 看内部怎么用——那 `.h` 就白分了。**注释的目的是让 `.h` 单独拿出来就能当说明书用。**

#### 4.3.4 四种情形对照

**① 无参数 → 不写 `@param`**

```c
/**
 * @brief  读取 DS1302 当前时间，结果存入全局数组 DS1302_Time[]
 * @retval None
 * @note   数组下标含义：0秒 1分 2时 3日 4月 5星期 6年
 */
void DS1302_ReadTime(void)
{

}
```

**② 单个参数**

```c
/**
 * @brief  蜂鸣器鸣叫指定时长
 * @param  ms 鸣叫时长，单位毫秒，建议 50 ~ 500（超过 1000 会明显卡住主循环）
 * @retval None
 */
void BEEP_Beep(unsigned int ms)
{

}
```

**③ 多个参数 → 顺序与定义一致**

```c
/**
 * @brief  LCD1602 在指定行、列显示字符串
 * @param  Line   显示行，取值 1 或 2
 * @param  Column 起始列，取值 0 ~ 15
 * @param  String 待显示字符串首地址，有效长度不超过 (16 - Column)
 * @retval None
 * @note   需先调用 LCD1602_Init()，否则显示乱码
 */
void LCD1602_ShowString(unsigned char Line, unsigned char Column, char *String)
{

}
```

**④ 指针 / 数组参数 → 必须写"长度限制"**

C 语言传数组只传首地址，函数内部根本不知道数组多长，**长度约束只能靠注释告知调用者**：

```c
/**
 * @brief  通过串口发送一段数据
 * @param  buf 待发送数据缓冲区首地址
 * @param  len 发送字节数，取值 1 ~ 64（受限于发送缓冲区大小）
 * @retval 实际发送的字节数
 */
unsigned char UART_SendBuf(unsigned char *buf, unsigned char len)
{

}
```

#### 4.3.5 `@retval` 写法

有返回值的函数，要写清"每个返回值代表什么"，而不是笼统写"有返回值"：

```c
/**
 * @brief  扫描按键
 * @retval 0 无按键按下
 * @retval 1 按键 K1 按下
 * @retval 2 按键 K2 按下
 */
unsigned char KEY_Scan(void)
{

}
```

无返回值写 `@retval None`；**永远不要**写"有返回值"这种无信息量的话。

#### 4.3.6 三个高频错误

1. **漏写有参函数的 `@param`**——函数括号里不是 `void`，就必须有 `@param` 行。
2. **参数顺序写反**——照函数定义抄一遍最保险，Doxygen 生成的文档靠这个对齐。
3. **只写了一半**——3 个参数只写了 2 行。自查方法：**数括号里的逗号，逗号数 + 1 = `@param` 行数**（函数指针参数内部的逗号除外）。

#### 4.3.7 简写版（团队二选一，不要混用）

仅限**无参数、逻辑极简的私有函数**（`static`），可用单行注释：

```c
/* 读取 DS1302 当前时间，结果写入全局数组 DS1302_Time[] */
void DS1302_ReadTime(void)
{

}
```

对外接口（`.h` 里声明的函数）一律用完整模板，不得简写。

### 4.4 宏与全局变量注释

```c
#define BEEP_PORT       P2_5        // 蜂鸣器控制引脚，1=响
#define LCD_ADDR        0x4E        // LCD1602 I2C 从机地址
#define KEY_SCAN_PERIOD 10          // 按键扫描周期，单位 ms

unsigned char Alarm_Hour = 20;      // 闹钟小时，范围 0~23
unsigned char Alarm_Min  = 30;      // 闹钟分钟，范围 0~59
bit           Alarm_Flag = 0;       // 闹钟触发标志，1 表示到点待响
```

**原则**：注释放右侧，一句话说清"是什么 + 单位 / 范围"，同类声明整体对齐，不换行。

### 4.5 文件内分区注释

`.c` 内部用统一格式的分区线划分区块，便于跳转定位（Keil 中可折叠）：

```c
/* ==================== 私有宏与变量 ==================== */
/* ==================== 私有函数声明 ==================== */
/* ==================== 对外接口实现 ==================== */
/* ==================== 私有函数实现 ==================== */
```

分区名与 §3.3 的九段顺序对应；同一工程内分区线格式保持一致（四个等号，前后各一空格）。

### 4.6 注释自查

- [ ] 每个 `.c/.h` 有完整文件头（§4.2 字段表逐项）
- [ ] 每个对外函数有 `@brief` / `@param` / `@retval`
- [ ] 有参函数 `@param` 行数 = 逗号数 + 1，顺序一致
- [ ] 指针 / 数组参数写明了长度限制
- [ ] 无"i++ // i自增"这类废话注释；时序、魔法数字、易错点已注释
- [ ] 文件内有分区线

## 5. 中断服务函数

### 5.1 与普通函数的本质差异

| 维度 | 普通函数 | 中断服务函数 |
|:---|:---|:---|
| 参数 | 可以带 | **必须是 `void`，禁止带参数** |
| 返回值 | 可以有 | **必须是 `void`，禁止有返回值** |
| 函数名 | 自己起 | **固定不可改**（由中断号或启动文件向量表决定） |
| 谁调用它 | 你写的代码 | **硬件自动跳转**，代码里永远不会出现调用语句 |
| 执行时机 | 你决定 | **随机插入**，主程序随时被打断 |
| 执行时长 | 不限 | **越短越好，微秒级**，否则主程序卡死 |
| 注释要素 | `@brief` `@param` `@retval` | **只有 `@brief` 和 `@note`** |

结论：**中断函数不写 `@param`，也不写 `@retval`——因为它本来就没有。** 这是 §4.3.2"无参函数整行不写 `@param`"的一个特例。

### 5.2 C51 模板与中断号

```c
/**
 * @brief  定时器0中断服务函数，每 1ms 触发一次
 * @note   中断号 1；仅重装初值 + 置标志，执行时间 < 10us
 *         禁止在此调用 Delay() 或任何阻塞函数
 */
void Timer0_Routine(void) interrupt 1
{
    static unsigned int T0Count = 0;

    TH0 = 0xFC;                 /* 重装初值，1ms @ 12MHz */
    TL0 = 0x18;

    T0Count++;
    if (T0Count >= 1000)        /* 累计 1000 次 = 1s */
    {
        T0Count = 0;
        Sec_Flag = 1;           /* 置标志，交由主循环处理 */
    }
}
```

**C51 中断号对照表**（写在 `@note` 里便于日后核对）：

| 中断号 | 中断源 | 触发引脚 / 条件 |
|:---|:---|:---|
| `interrupt 0` | 外部中断 0 | INT0，P3.2 |
| `interrupt 1` | 定时器 0 | T0 溢出 |
| `interrupt 2` | 外部中断 1 | INT1，P3.3 |
| `interrupt 3` | 定时器 1 | T1 溢出 |
| `interrupt 4` | 串口 | 收发完成 |

### 5.3 STM32 两种写法

**方案 A（江科大 / 正点原子风格）**：直接写在自己模块里。

```c
/**
 * @brief  TIM2 更新中断服务函数，1ms 触发一次
 * @note   函数名必须与启动文件 startup_stm32f10x_md.s 中向量表一致，改错则不进中断
 *         内部只清标志 + 置位，耗时 < 5us
 */
void TIM2_IRQHandler(void)
{
    if (TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)
    {
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);   /* 必须手动清标志，否则反复进中断 */
        Sec_Flag = 1;
    }
}
```

**方案 B（STM32CubeMX 风格）**：`stm32f1xx_it.c` 是自动生成的，**不要往里写业务逻辑**（重新生成会被覆盖），只在回调里写：

```c
/**
 * @brief  定时器更新回调，1ms 触发一次
 * @param  htim 触发回调的定时器句柄，本工程只用 TIM2
 * @note   由 HAL_TIM_IRQHandler 内部调用，不要在此加延时
 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        Sec_Flag = 1;
    }
}
```

> 方案 B 的回调**有参数**（`htim`），所以反而要写 `@param`。判断依据始终是"函数定义括号内是不是 `void`"，不靠记忆。

### 5.4 中断归哪个模块

**放在它所属的外设模块里，不要放 `main.c`。**

| 中断来源 | 放哪个文件 |
|:---|:---|
| 定时器 0 / 定时器 1 | `Timer.c` |
| 串口收发 | `UART.c` |
| 外部中断 INT0 / INT1 | `EXTI.c`（或对应按键模块） |
| ADC 转换完成 | `ADC.c` |
| STM32 的 `xxx_IRQHandler` | 方案 A 放自己模块；方案 B 留 `stm32f1xx_it.c`，逻辑写回调 |

**中断函数一般不在 `.h` 里声明**——没有任何代码会调用它（硬件跳转），声明出去只会让人误以为可以手动调用。

### 5.5 中断里能做什么、不能做什么

| 可以做 | 不可以做 |
|:---|:---|
| 清中断标志（必做） | 调用 `Delay()` 或任何延时 |
| 重装定时器初值 | 调用 `LCD1602_ShowString()` 等耗时外设操作 |
| 读写一个变量 / 标志位 | 调用 `printf`、串口发送长数据 |
| 把数据存入缓冲区 | 浮点运算（51 上极慢） |
| 置标志后立刻退出 | 死循环、`while` 等待 |

**标准做法是"中断置标志，主循环干活"**：

```c
/* Timer.c 里 */   Sec_Flag = 1;              /* 中断只管置位，1us 完成 */

/* main.c 里  */   if (Sec_Flag) { ... }      /* 主循环看到标志再干重活 */
```

### 5.6 三个坑

**坑 1：中断与主循环共享的变量必须加 `volatile`**

```c
volatile bit Sec_Flag = 0;          /* 中断改、主循环读，必须 volatile */
```

不加会怎样：编译器看到主循环里 `while (!Sec_Flag);` 期间没有任何代码修改 `Sec_Flag`，可能把它优化成"永真死循环"，中断里改了也不重新读——表现为"程序卡死不响应"。

**坑 2：16 位变量在 8 位机上读写不是原子的**

51 是 8 位机，读写 `unsigned int`（16 位）要分两条指令。若主循环正在读、中途被中断打断并改写，就会读到"高字节是旧值、低字节是新值"的撕裂数据。

对策：**跨中断共享的标志一律用 `bit` 或 `unsigned char`**：

```c
volatile bit          Sec_Flag  = 0;    /* ✅ 单 bit，原子 */
volatile unsigned char Adc_Ready = 0;   /* ✅ 单字节，原子 */
volatile unsigned int  Adc_Value = 0;   /* ⚠️ 读之前先关中断，或连读两次比对 */
```

**坑 3：中断里调用了"与主程序共用的非可重入函数"**

C51 函数默认**不可重入**：参数和局部变量在固定内存里分配，而不是每次调用压栈。若一个函数既被主程序调用、又被中断调用，两边同时执行时可能互相覆盖参数 / 局部变量，症状是"偶尔算出离谱的值"。

- `using n` 只指定寄存器组，**不能解决重入问题**，别把它当万能药。
- 对策 1（首选）：中断只置标志，不在中断里调用业务函数。
- 对策 2：确需共用时，把该函数声明为 `reentrant`（编译器改为栈上分配，51 上 RAM 开销大，慎用）。
- 对策 3：对共享数据在访问前后关 / 开中断，保证一次读写完整。
- 无论如何，中断里都不得出现 `Delay` / `printf` / 显示类函数 / `while` 等待。

### 5.7 中断自查

- [ ] 函数签名是 `void xxx(void)`，括号里没有参数
- [ ] 只写 `@brief` / `@note`，没有 `@param` / `@retval`
- [ ] `@note` 写明触发源（定时器溢出？引脚下降沿？）与触发频率
- [ ] 函数体里没有 `Delay` / `printf` / 显示类函数 / `while`
- [ ] 函数放在所属外设模块，没有放进 `main.c`
- [ ] 与主循环共享的变量已加 `volatile`，且用 `bit` 或 `unsigned char`

## 6. 串口模块

串口是唯一一个"写完就一直在用、而且靠它定位其他模块问题"的模块，注释要求比其他模块高。

### 6.1 归属：内置于 MCU 的放 `System/`

判断依据只有一条：

| 外设类型 | 归哪一层 | 例子 |
|:---|:---|:---|
| **外部器件**（要画在原理图上、要接引脚） | `Driver/` | LCD1602、DS1302、DS18B20、按键、蜂鸣器 |
| **MCU 内置外设**（芯片里自带，只需配寄存器） | `System/` | 串口、定时器、ADC、外部中断 |

所以：**`UART.c/.h` 放 `System/`**，地位和 `Timer.c` 一样——是"厨房的水电煤"，不是"一道菜"。

### 6.2 文件头必须写"通信参数"

串口是唯一必须把**通信参数**写进文件头的模块：参数不匹配就全是乱码，而参数是靠寄存器配出来的，代码一改注释就过时。

```c
/**
 * @file    UART.c
 * @brief   串口通信驱动，提供初始化、单字节收发、字符串发送
 * @author  FREEDOM
 * @version V1.0
 * @date    2026-11-11
 * @note    【通信参数】波特率 9600 / 8 位数据 / 1 位停止 / 无校验
 *          晶振 11.0592MHz（若改用 12MHz 则 9600 误差达 8.5%，通信必失败）
 *          引脚：P3.0 RXD 接收，P3.1 TXD 发送
 *          依赖：Timer1 被用作波特率发生器，不可另作普通定时器使用
 */
```

`@note` 里的 **「波特率 / 数据位 / 停止位 / 校验位 + 晶振频率」** 是必写项，缺一项都可能让后来的人白调半天。

### 6.3 初始化与波特率

```c
/**
 * @brief  串口初始化，配置为模式1（8位UART，波特率可变）
 * @param  baud 目标波特率，取值 4800 / 9600 / 19200
 *              （更高波特率需改 SMOD，见 UART_SetBaudRate）
 * @retval None
 * @note   SCON = 0x50 → 模式1 + 允许接收；定时器1 工作在模式2（8位自动重装）
 */
void UART_Init(unsigned int baud)
{
    SCON = 0x50;        /* 0101 0000：模式1，REN=1 允许接收 */
    TMOD &= 0x0F;       /* 清定时器1 的 4 位，不影响定时器0 */
    TMOD |= 0x20;       /* 定时器1 设为模式2：8 位自动重装，作波特率发生器 */
    TH1  = 0xFD;        /* 11.0592MHz / 9600bps → 重装值 0xFD，误差 0% */
    TL1  = 0xFD;
    TR1  = 1;           /* 启动定时器1 */
}
```

**波特率重装值怎么来的（写清楚，别让人怀疑）**：

```
波特率 = (2^SMOD / 32) × (fosc / 12) / (256 - TH1)

11.0592MHz、SMOD=0、9600bps 时：
  fosc/12   = 921600
  921600/32 = 28800
  28800 / 9600 = 3  →  256 - TH1 = 3  →  TH1 = 253 = 0xFD  （误差 0%）

换成 12MHz 晶振时：
  fosc/12   = 1000000
  1000000/32 = 31250
  31250/3   = 10416.7  →  误差 (10416.7 - 9600)/9600 = 8.5%  ✗ 超过 5%，通信失败
```

**这就是 51 开发板必须用 11.0592MHz 晶振的原因——它是 9600 的整数倍，误差为 0；12MHz 做不到。** 这条写进注释里，比"照抄代码"有价值得多。

### 6.4 `printf` 重定向

```c
/**
 * @brief  C51 的 putchar 重定向，使 printf 从串口输出
 * @param  c 待发送的单字节字符，由 printf 内部传入
 * @retval 原样返回 c，满足 stdio 约定
 * @note   必须在 Keil 的 Target Options 中勾选 "Use MicroLIB"，
 *         否则 printf 会链接标准库，占满 8KB Flash
 */
char putchar(char c)
{
    SBUF = c;           /* 写入发送缓冲，硬件自动开始发送 */
    while (!TI);        /* 等待发送完成；死等，勿在中断中调用本函数 */
    TI = 0;             /* 软件清发送完成标志 */
    return c;
}
```

> 注释里那两行 `@note` 是最容易漏的：不勾 MicroLIB 会编译报错或撑爆 Flash；在中断里调 `printf` 会因为死等而卡住整个系统。

### 6.5 接收中断

```c
/**
 * @brief  串口接收中断服务函数，收到一字节即触发
 * @note   中断号 4；读 SBUF 会自动清 RI，代码里显式写 RI=0 只是更直观
 *         只做"存数据 + 置标志"，帧解析放主循环，避免占用中断时间
 */
void UART_Routine(void) interrupt 4
{
    if (RI)                     /* 是接收触发，不是发送触发 */
    {
        RI = 0;                 /* 清接收标志（读 SBUF 会自动清，显式写便于阅读） */
        Rx_Buf[Rx_Cnt++] = SBUF;
        if (Rx_Cnt >= RX_BUF_SIZE)
        {
            Rx_Cnt = 0;
        }
        Rx_Flag = 1;            /* 置标志，主循环负责解析 */
    }
    if (TI)                     /* 发送完成也进这个中断，要单独处理 */
    {
        TI = 0;
    }
}
```

共享变量声明必须带 `volatile`：

```c
volatile unsigned char Rx_Flag = 0;         /* 中断置位、主循环清零 */
volatile unsigned char Rx_Cnt  = 0;
volatile unsigned char Rx_Buf[RX_BUF_SIZE]; /* 中断写、主循环读 */
```

### 6.6 五个高频坑

| 坑 | 现象 | 原因与对策 |
|:---|:---|:---|
| 1. 晶振用 12MHz 配 9600 | 全是乱码 | 误差 8.5%，超 5% 上限；换 11.0592MHz 或改用其他波特率 |
| 2. `while(!TI)` 卡死 | 程序停在发送函数里出不来 | 忘了 `TR1=1` 或串口没初始化；`printf` 只在初始化之后调用 |
| 3. 中断里调 `printf` | 系统整体卡顿或死锁 | 中断里死等发送，主程序无法运行；改为置标志、主循环打印 |
| 4. 接了发送中断却没清 `TI` | 反复进中断，主程序几乎不执行 | 中断里必须同时处理 `RI` 和 `TI` 两种情况 |
| 5. 多字节数据无帧头帧尾 | 收到的数据错位、粘包 | 加帧头（如 `0xAA`）和校验，或固定长度帧 |

### 6.7 串口自查

- [ ] 文件头 `@note` 写全 **波特率 / 数据位 / 停止位 / 校验 / 晶振频率**
- [ ] `UART_Init` 的 `@param baud` 写了可选范围，而不是只写"波特率"
- [ ] `putchar` 的 `@note` 提醒勾 **Use MicroLIB**
- [ ] 接收中断同时处理了 `RI` 和 `TI`
- [ ] `Rx_Flag`、`Rx_Cnt`、`Rx_Buf` 已加 `volatile`
- [ ] 没有在中断里调用 `printf`

## 7. Keil 落地与编辑器配置

### 7.1 把文件加进工程

这是最容易卡住的一步——文件写好了，但编译说找不到函数。

| 步骤 | 操作 | 说明 |
|:---:|:---|:---|
| ① 建文件 | 在工程目录建 `LED.c`、`LED.h` … | 用外部编辑器（VS Code）建也行 |
| ② 加 `.c` | 左侧 Project 树 → 右键 `Source Group 1` → **Add Existing Files to Group 'Source Group 1'** | **每个 `.c` 都必须加**，`.h` 不用加 |
| ③ 加目录 | Project → Options for Target → **C51** → **Include Paths** 添加文件夹 | 否则 `#include "LED.h"` 找不到 |
| ④ 编译 | F7 / Build | 链接器自动把各 `.obj` 拼起来 |

### 7.2 编译链接发生了什么

```
led.c ──编译──> led.obj ─┐
key.c ──编译──> key.obj ─┼─链接器─> 最终 .hex
main.c ─编译──> main.obj ┘
```

- `.h` **不参与编译**，它只是被 `#include` **原样文本复制**进 `.c`（所以叫"头文件"）。
- 每个 `.c` 独立编译，互不知道对方写了什么，只知道头文件承诺的接口。
- 链接器最后按**符号名**把"调用"接到"定义"上，所以编译顺序无所谓，但**必须都在工程里**。

### 7.3 VSCode 自动生成函数注释（Doxygen 风格）

安装插件 **Doxygen Documentation Generator**，在 `settings.json` 中配置：

```json
"doxdocgen.c.commentPrefix": " * ",
"doxdocgen.c.firstLine": "/**",
"doxdocgen.c.lastLine": " */",
"doxdocgen.c.triggerSequence": "/**",
"doxdocgen.generic.authorName": "FREEDOM",
"doxdocgen.generic.authorTag": "@author {author}",
"doxdocgen.file.fileTemplate": "@file {name}",
"doxdocgen.generic.briefTemplate": "@brief ",
"doxdocgen.generic.paramTemplate": "@param {param} ",
"doxdocgen.generic.returnTemplate": "@retval "
```

在函数上一行输入 `/**` 后回车，自动生成注释骨架（`@param` 行会按实际参数个数自动生成，不用手数），只需补写范围和单位。

> 作业提交前，把 `authorName` 改成 `詹诗意` 即可一次性切换全部署名。

### 7.4 Keil 编辑器设置（编码 / Tab / 空格）

`Edit → Configuration → Editor`：

- `Encoding` 选 **UTF-8**（与工程现有文件一致；选 ANSI 会把中文注释显示成乱码）
- `Tab Size` 设为 4
- 取消勾选 `Insert Tab`（改为插入空格）
- 勾选 `Show Whitespaces` 便于检查对齐

## 9. 本库硬件对照（照抄示例前先核对）

示例代码里的引脚是通用占位，**普中 A2 的实际连接如下**，直接照抄前先对照：

| 模块 | 引脚 | 有效电平 / 驱动 | 注意 |
|:---|:---|:---|:---|
| LED D1 ~ D8 | P2.0 ~ P2.7 | 低电平点亮（灌电流） | 与数码管位选、蜂鸣器共用 P2 口 |
| 蜂鸣器 | P2.5 | ULN2003D 反相驱动，`P2.5 = 1` 时鸣叫 | 无源型，必须给方波；与 LED D6 共用 |
| 独立按键 K1 ~ K4 | P3.1 / P3.0 / P3.2 / P3.3 | 低电平表示按下 | 机械抖动，需软件消抖 |
| 数码管段选 | P0 | 经 74HC245 缓冲，共阴 | — |
| 数码管位选 | P2.2 / P2.3 / P2.4 | 经 74HC138 译码 | 与 LED D3/D4/D5 共用 |
| LCD1602 控制口 | P2.6 RS / P2.5 RW / P2.7 E | 8 位并口，数据走 P0 | **P2.5 与蜂鸣器冲突，二者不能同时使用** |
| 矩阵按键 | P1 | 4×4，行列扫描 | — |

> 详细接线与原理见 [[模块原理图]]；具体实验代码见 [[蜂鸣器]]、[[按键]]、[[动态数码管]]。
